# SitePulse — Laravel App

WordPress Site Auditor SaaS. A WordPress plugin reports health metrics (plugins, DB size, PHP errors, SSL status), this Laravel app stores audit history and renders reports with recommendations. Alerts are sent via email and Slack/Discord webhooks for critical issues (plugin vulnerabilities, SSL expiry, site down).

## Running the App

All commands run inside Docker. The app is at `http://sitepulse-app.test:6080/` (or `http://localhost:6080/`).

```bash
# Start
dc up -d --build

# Stop
dc down

# Run artisan
docker compose exec php php artisan <command>

# Run migrations
docker compose exec php php artisan migrate

# Tail logs
docker compose exec php php artisan pail

# Open tinker
docker compose exec php php artisan tinker

# Run tests
docker compose exec php php artisan test

# Frontend dev (runs inside container via composer dev)
docker compose exec php composer dev
```

`dc` is aliased to `docker compose` in this project.

## Architecture

### Backend (Laravel)

```
app/
├── Actions/          # Single-purpose action classes
├── Http/
│   ├── Controllers/
│   │   ├── Settings/   # Profile, Security
│   │   └── Teams/      # Team CRUD, members, invitations
│   └── Middleware/
├── Models/
│   ├── User.php          # Has 2FA, belongs to teams
│   ├── Team.php          # Slug-routed, soft-deletes
│   ├── Membership.php    # Pivot: team_members table
│   └── TeamInvitation.php # Code-based invites, 3-day expiry
└── Enums/
    └── TeamRole.php      # Owner | Member | Guest
```

Routes:
- `routes/web.php` — main web routes, dashboard under `/{team_slug}/dashboard`
- `routes/settings.php` — profile, security, appearance, team management
- `routes/console.php` — Artisan scheduled commands (add audit jobs here)

### Frontend (React + Inertia)

```
resources/js/
├── app.tsx           # Inertia entry point — layout resolver
├── pages/            # One file per route
├── components/       # Shared components (ui/ = base, root = app-specific)
├── layouts/          # AppLayout (sidebar), AuthLayout, SettingsLayout
├── hooks/            # Custom hooks
├── actions/          # TS mirrors of Laravel controllers (auto-generated by Wayfinder)
├── routes/           # Type-safe route helpers (auto-generated by Wayfinder)
└── types/            # Shared TypeScript types
```

**Layout resolution** (`app.tsx`):
- `welcome` → no layout
- `auth/*` → `AuthLayout`
- `settings/*`, `teams/*` → `AppLayout` + `SettingsLayout`
- everything else → `AppLayout` (includes sidebar)

Pages export a static `.layout` property for breadcrumbs/titles — this is read by the layout component, not by Inertia directly.

### Multi-Tenancy (Teams)

- Every user has a personal team created on registration
- URLs are prefixed with `{current_team}` slug: `/{team-slug}/dashboard`
- `EnsureTeamMembership` middleware protects team-scoped routes
- Roles: `Owner`, `Member`, `Guest` (via `TeamRole` enum)
- Invitations: code-based, 3-day expiry, email notification on send

## Key Patterns

### Adding a new page

1. Create `app/Http/Controllers/MyController.php` with an `__invoke` or named methods
2. Add route in `routes/web.php` (or `routes/settings.php`)
3. Run `php artisan wayfinder:generate` to update TS route helpers
4. Create `resources/js/pages/my-page.tsx` — export default component + optional `.layout` for breadcrumbs
5. The layout (sidebar etc.) is applied automatically based on page name prefix in `app.tsx`

### Adding a background job

1. `php artisan make:job MyJob`
2. Dispatch via `MyJob::dispatch()` or schedule in `routes/console.php`
3. Queue runs via `php artisan queue:work` (started by `composer dev`)

### Running Wayfinder (route/action type generation)

```bash
docker compose exec php php artisan wayfinder:generate
```

This regenerates `resources/js/actions/` and `resources/js/routes/` from Laravel routes.
